# 开发问题记录

## Tailwind CSS 高度 calc 不生效

**问题：** `h-[calc(100%-56)]` 不生效

**原因：** `56` 缺少单位，应为 `56px`

**解决：** `h-[calc(100%-56px)]`

> 注意：Tailwind 对 `calc()` 有特殊处理，会自动在运算符两侧加空格，所以 `calc()` 内**不需要**用下划线 `_` 代替空格，直接写 `calc(100%-56px)` 即可。

**更优方案：** 用 flex 布局，`main` 设 `flex-1` 自动撑满剩余高度，无需手动计算。

## Vue 组件名 lint 报错：应是多词组件名

**问题：** `Component name "Icon" should always be multi-word`（`vue/multi-word-component-names`）

**原因：** Vue ESLint 插件要求组件名必须由多个单词组成，但 Iconify 的 `Icon` 是单单词组件名。

**解决小技巧：** 在 `eslint.config.ts` 中关闭该规则：

```ts
{
  name: 'custom/lint',
  rules: {
    'vue/multi-word-component-names': 'off'
  }
}
```

## 使用 `import.meta.glob` 做插件化自动注册

**场景：** `src/materials` 下的每个物料目录都提供一个统一的 `install(register)` 方法，希望入口文件自动收集并注册，而不是每新增一个物料都手动 `import` 一次。

**实现：**

```ts
const materialModules = import.meta.glob<MaterialModule>('./*/index.ts', {
  eager: true,
})

Object.values(materialModules).forEach((module) => {
  module.install(register)
})
```

**用途：**

- 适合做插件化注册、模块自动发现、按目录约定收集能力。
- 适合“每个子模块都暴露统一入口”的场景，比如物料、路由、指令、图表组件、区块配置等。
- 新增 `src/materials/xxx/index.ts` 后，只要它实现了同样的 `install` 方法，入口文件无需再修改。

**关键点：**

- `import.meta.glob('./*/index.ts')` 会匹配当前目录下所有子目录的 `index.ts` 文件。
- `eager: true` 表示在模块初始化阶段直接导入这些文件，这样可以立刻执行注册逻辑；如果不加，拿到的是懒加载函数，还需要再手动调用。
- `import.meta.glob<MaterialModule>()` 可以显式声明模块类型，这样 `module.install(register)` 就不会出现“类型 unknown 上不存在属性 install”的报错。

**对比手动导入：**

- 手动导入适合模块数量少、入口关系固定的场景。
- `import.meta.glob` 更适合目录会持续扩展、希望遵循约定自动接入的场景，可减少入口文件反复维护。

**这次项目里的收益：**

- `src/materials/index.ts` 只负责定义类型、提供 `register`、执行自动安装。
- 各物料目录只关注自己的物料定义和 `install` 实现，职责更清晰。

## Vue 3 生命周期可以嵌套注册

**问题：** 生命周期钩子能不能写在另一个生命周期里？

**示例：**

```ts
onMounted(() => {
  onUnmounted(() => {})
})
```

**结论：**

- `onUnmounted()` 可以写在 `onMounted()` 内部，这在 Vue 3 里是允许的。
- 适合“某个清理逻辑就是为这次挂载时创建的对象服务”的场景。
- 常见于 `ResizeObserver`、事件监听、定时器、第三方实例销毁。

## 画布场景里，结合 `ResizeObserver` 维护响应式宽高

**问题：** 画布容器尺寸会变化，怎么把容器尺寸和画布样式联动起来？

**示例：**

```ts
const canvasRootRef = useTemplateRef('canvasRoot')

const rectWidth = ref(1000)
const rectHeight = ref(800)

const canvasWidth = ref(1920)
const canvasHeight = ref(1080)

const canvasStyle = computed(() => {
  return {
    width: canvasWidth.value + 'px',
    height: canvasHeight.value + 'px',
  }
})

onMounted(() => {
  const { width, height } = canvasRootRef.value.getBoundingClientRect()
  rectWidth.value = width
  rectHeight.value = height

  const ob = new ResizeObserver((entries) => {
    const entry = entries[0]
    const rect = entry.contentRect
    rectWidth.value = rect.width
    rectHeight.value = rect.height
  })

  ob.observe(canvasRootRef.value)

  onUnmounted(() => {
    ob.disconnect()
  })
})
```

**思路：**

- `canvasRootRef` 指向真实画布容器，用来拿初始尺寸、监听后续变化。
- `rectWidth`、`rectHeight` 存“容器当前实际尺寸”。
- `canvasWidth`、`canvasHeight` 存“业务上的画布尺寸”。
- `canvasStyle` 用 `computed` 从 `canvasWidth`、`canvasHeight` 派生出样式对象。
- `ResizeObserver` 负责监听容器变化，并持续更新 `rectWidth`、`rectHeight`。

**这样拆的好处：**

- 容器尺寸和画布尺寸职责分开，不容易混。
- 后面做缩放、自适应、滚动区域、标尺联动时会更清晰。
- 样式通过 `computed` 统一生成，比到处手动改 DOM 更稳。
