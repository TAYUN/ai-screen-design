# 开发日志

本目录记录项目开发过程中的阶段性进度。一个功能使用一个主日志文件；同一功能后续的优化、修复和验证在原日志中按日期追加阶段记录。只有功能主题完全不同，或原日志已经不适合继续维护时，才新增日志文件。日志索引按功能主题维护，按最近一次进展倒序排列。

## 记录原则

- 记录实际变更、设计取舍、验证结果和后续事项，便于回顾与交接。
- 区分“已完成”“待确认”和“未验证”；未提交的工作区改动只代表进行中的开发内容。
- 一篇日志聚焦一个功能主题，不要求一次完成。
- 同一功能的多次开发按日期追加阶段记录，分别说明本次变更、验证结果和遗留问题。
- 日志索引中的日期表示最近一次进展日期，状态表示该功能当前整体状态。

## 命名规则

首次创建日志时，文件名格式为 `YYYY-MM-DD-主题.md`，主题使用小写英文短横线，例如：`2026-08-15-property-panel.md`。后续同一功能的开发继续使用原文件，不重复创建日期文件。

## 记录模板

```md
# 功能主题名称

- 首次创建：YYYY-MM-DD
- 最近进展：YYYY-MM-DD
- 状态：进行中 / 已完成 / 阻塞
- 关联提交：未提交 / <commit hash>

## 目标

说明这个功能要解决的问题或交付内容。后续阶段继续围绕这个目标补充记录。

## 总体设计

- 长期有效的架构、数据结构和交互约定。

## 阶段记录

每次继续开发时追加一个日期小节：

### YYYY-MM-DD 阶段名称

- 目标：本阶段要完成的内容。
- 已完成：具体改动及影响范围。
- 设计与取舍：本阶段的关键选择。
- 验证：命令、手工步骤和结果；明确未验证部分。
- 已知问题：本阶段发现但暂不处理的问题。

## 后续事项

- 跨阶段持续存在的待办、已知限制或下一步。阶段性问题优先记录在对应阶段下。
```
