# 撤销重做

- 首次创建：2026-08-17
- 最近进展：2026-08-19
- 状态：进行中
- 关联提交：03627a0

## 目标

为编辑器变更提供可撤销、可重做的历史记录能力，并覆盖属性编辑和画布节点操作。

## 总体设计

- 历史栈放在组合式函数模块作用域中，使属性表单和工具栏实例共享同一份操作历史。
- 每条记录保存 `target`、`key`、`oldValue` 和 `newValue`，复用现有 `getValue` / `setValue` 处理嵌套字段路径。
- 同一功能的后续优化继续追加到本文件，不按每次开发拆分日志文件。

#### 已知问题

- **[P1] 缩放的宽高不会被正确记录，撤销后尺寸无法恢复**
  - `useMoveable.ts` 先直接修改 `node.layout.width/height`，随后才调用 `applyChange`。此时 `oldValue` 已经是新尺寸，`applyChange` 会因新旧值相同直接返回。
  - 结果是缩放时宽高不进入历史栈；随后 `onDrag` 只会记录位置，撤销只能回退位置，不能回退尺寸。
- **[P1] `commitBatch` 在没有活动批次时会直接抛异常**
  - `useUndoRedo.ts` 无条件读取 `activeBatch.length`，但 `activeBatch` 初始为 `null`，提交后也会重置为 `null`。
  - 目前 Moveable 和表单事件通常成对触发，但事件中断、组件销毁或未来任意遗漏 `startBatch` 的调用，都会导致运行时错误。这里应把无活动批次视为无操作。
- **[P2] 重做批次使用反向顺序，语义不对**
  - `useUndoRedo.ts` 重做也使用了 `toReversed()`。撤销应倒序恢复旧值；重做应按原始顺序重放新值。
  - 当前多节点布局记录彼此独立，短期不一定显现，但一旦批次中出现依赖顺序的修改，就会产生错误结果。
- **[P2] 批次状态是组合式函数实例私有的，但历史栈是全局共享的**
  - `useUndoRedo.ts` 的 `activeBatch` 每次调用 `useUndoRedo()` 都重新创建，而撤销栈和重做栈是模块级共享的。
  - 目前 Moveable 和表单各自开始、提交自己的批次，基本可用；但两个来源在同一时间段内改动时，历史栈没有批次协调机制。至少应明确不支持嵌套/并发批次，避免后续功能误用。
